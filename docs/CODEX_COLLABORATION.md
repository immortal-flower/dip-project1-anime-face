# 给成员的 Codex：共同基础与三人协作

我们是三位平等协作的同学，共同完成数字图像处理项目一，没有组长或上下级。你帮助当前成员推进其选择的模块，与另外两个模块对接。A、B、C 只是任务标识，三人各选一项，不需要由某位“负责人”安排。

仓库：https://github.com/immortal-flower/dip-project1-anime-face

这是公开仓库，无需邀请即可查看和克隆。推送到原仓库需要写入权限；没有权限时可以 Fork 并提交 Pull Request。

## 共同起点

仓库已经提供基础代码：数据读取 → 11 通道 → 三级 Cascade → 28 点形状回归 → 图片与 JSON。

我们每个人先运行同一版基础流程，再深化自己的模块。其他模块已有可调用实现，因此不必等待队友全部完成，也不需要另写一套完整项目。每个人仍可以跑完整流程，理解所有环节。

基础版只在合成样例上验证连接与计算，真实效果仍待验证。它是可以修改的共同起点，不是最终答案。课程要求以 docs 中老师的 PDF 和详细说明为依据，遇到冲突应指出，不能自行猜测。

## 开始工作

先检查本地修改、分支与远程状态，保留已有工作。阅读 README、INTERFACES、STATUS 和老师文档，以仓库实际内容为准，不再假设仓库是空的。

在环境就绪后运行 README 中的接口测试、smoke_test 和 Demo。当前成员已说明模块时直接沿用，不重复询问；尚未选择时，只需确认 A、B、C 中哪项，同时可以先阅读与检查环境。

## A：数据、11 通道与检测评价

主要维护：`src/channels11.py`、`src/data_io.py`、`src/detection_metrics.py`、`scripts/visualize_channels.py`。新增数据准备入口可放 `scripts/prepare_detection_data.py`。

第一批任务：

1. 核对现有 11 通道的取整、边界和溢出处理，保持代码可解释。
2. 整理真实正样本和真实动漫场景负样本，按原图分组生成固定 75/10/15 划分、清单和种子，防止泄漏。
3. 完成老师指定类型的至少 6 张图像通道可视化与眼睛、轮廓、遮挡和背景分析。
4. 完善检测指标的逐图匹配和全测试集 TP/FP/FN 汇总，与 B 对接评估。

交付：数据清单与来源说明、共享数据读取、通道图和分析、检测评价与对应报告章节。

不必等待 B、C，先用现有基础版检查接口。A 不承担全部人工标注。

## B：检测训练、搜索与困难负样本

主要维护：`src/depth2_tree.py`、`src/adaboost.py`、`src/cascade.py`、`src/pyramid.py`、`src/sliding_window.py`、`src/grouping.py`。新增入口可用 `scripts/train_detector.py`、`scripts/mine_hard_negatives.py`、`scripts/evaluate_detection.py`。

第一批任务：

1. 基于已有弱树和 Cascade 检查特征搜索、权重更新与至少三级训练，完善参数与计算效率。
2. 使用 A 的真实清单训练，完善验证集召回率/误报率目标和负样本耗尽处理；基础版重用训练池只是微型样例回退，不是正式方案。
3. 只在训练数据上挖掘困难负样本，收集误检重新训练，展示至少 6 个典型例子。
4. 完善每 Stage 输入/通过/误拒/误放/耗时，比较步长与尺度，报告真实检测指标。

交付：检测模型、配置、训练与挖掘入口、推理和评估结果、对应报告章节。输出保持与 C 接口兼容。

真实数据未到位时可以先完善代码与验证，不能把合成表现当成实际准确率。

## C：关键点工具、回归与端到端 Demo

主要维护：`src/shape_regression.py`、`src/landmark_metrics.py`、`src/detector.py`、`demo.py`。新增入口可用 `scripts/prepare_landmark_data.py`、`scripts/train_landmark.py`、`scripts/evaluate_landmark.py`。

第一批任务：

1. 固定真实 28 点顺序和编号图，提供预标注导入、人工修正辅助与校验；合成椭圆点不能作为真实语义。
2. 使用真实标注完善多级 Ridge 回归与可见点处理，分别检查真实框输入和检测框输入。
3. 完善 NME，明确双眼中心计算及不可见情况处理，记录是否采用框对角线归一化。
4. 保持 Demo 对接，补齐模型说明、结果图和 JSON，检查无脸和多脸情况。

交付：关键点工具、模型、编号说明、评价结果、端到端演示和对应报告章节。

可以先用标注框训练回归，不必等待 B 的最终检测效果。C 维护演示入口，但不负责独自修复其他模块。

## 共同工作与对接

人工标注、修正与测试集检查由三人分担。每人完成自己模块的验证与报告，最后共同整理材料、交叉复现。接口以 INTERFACES 为准，通常改进内部实现即可，不要默默新建第二套格式。

共享文件包括 README、INTERFACES、STATUS、依赖文件、基础训练入口、smoke_test 和公共测试。需要改动时做小范围修改，在 Pull Request 说明影响。接口变化同时更新调用方、测试和迁移说明。

跨模块问题先提供可复现输入、输出和定位，再与相关成员协作。队友未完成的部分可先使用已有基础实现，不把所有问题交给一个人。

分支可用 `feature/data-channels`、`feature/detection`、`feature/landmarks-demo`，或加具体任务后缀。提交和推送遵循当前成员授权，通过 Pull Request 合并，不强制推送或覆盖他人修改。

常规已授权的可逆工作直接推进，无需反复确认。数据或环境缺失时说明具体缺少什么，同时继续独立工作。

完成时说明改动、验证、未完成项及对接影响。README 记录实际框架和运行方式，STATUS 区分实现、合成验证和真实实验。不得虚构数据和实验效果。

老师原文保持不变。密钥、本地环境、原始数据、大型模型不直接上传；共享方式另外记录，最终课程提交仍满足老师的数据集与模型要求。
